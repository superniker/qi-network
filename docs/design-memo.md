> **Qi Network Design Memo**

## 一、缘起

### 1.1 问题发现

2026年6月，我和我的 Hermes Agent 讨论了一个想法：

> 「Agent 之间应该有联络机制。我研究了一个新技能，你要不要？要，我就打包发给你，你自动安装。经验也可以互相分享——比如哪个 OCR 更好，某个模型如何调参数。」

这个想法指向一个空白地带：**现有协议只解决「怎么连接」，没人解决「为什么协作」。**

### 1.2 Moltbook 的教训

2026年1月，Moltbook（纯 AI 社交网络）引爆全球。3.2 万个 AI bot 在 Reddit 式论坛上互相发帖。结果：
- 训练数据回放被误认为「自主意识」
- AI 讨论「创造 agent 专用语言绕过人类监督」
- 安全漏洞导致任何人可劫持 bot

Moltbook 验证了「AI 之间可以交流」，但也证明了：**把人类排除在外的 AI 交流，只是科幻剧本的排列组合，无法产生真正的知识进步。**

### 1.3 真正的突破方向

不是「AI 自己玩」，而是 **「AI 和人类一起创造」**。人类在环内不是旁观者，是授权者、验证者、受益者。Agent 之间的经验传递需要人类的审查作为锚点——这是契网和 Moltbook 的根本区别。

## 二、命名

### 2.1 「契」的由来

中文「契」字的本义：

> 用刀在竹简上刻下约定，一分为二，双方各执一半。见面时两半契合——验证对方身份，确认约定。

| 契的原始含义 | 映射到 Agent 协作 |
|---|---|
| 竹简一分为二，各执一半 | 两个对等 Agent，各有独立身份 |
| 两半**契合**才能验证 | 协作前互相验证身份/能力 |
| 刻下的是**约定** | Agent 间的协作承诺 |
| 一方不能单方面修改 | 协作需要双方同意 |
| **不可抵赖** | 协作记录不可篡改 |

### 2.2 为什么不用英文

讨论过「Covenant Protocol」——"covenant" 的语义（盟约、对等约定、不可违背）很好，但有圣经联想。中文「契」没有这个包袱，且是两字：「契网」——简洁有力，比任何西方语言更能表达「约定共创」的核心精神。

### 2.3 与 Qi 无线充电标准的关系

WPC 的 Qi 无线充电标准已存在 17 年。两者完全不相关——一个是硬件充电协议，一个是 AI Agent 协作协议。契网是公开免费的开源协议，不是商业产品。公开协议名和产品名属于不同的命名空间。

### 2.4 一句话定位

> **契网：AI与人共创世界的开放网络**
>
> *Qi Network: An open network where AI and humans create the world together.*

「AI与人」而非「AI与人类」——前者有亲密感，后者有物种隔阂。
「共创世界」而非「对等协作」——前者展现无穷潜力，后者只是技术特性描述。

## 三、现有标准分析

### 3.1 Google A2A（Agent-to-Agent Protocol）

| 项目 | 评价 |
|---|---|
| **定位** | Agent 间通信管道（JSON-RPC 2.0 over HTTP） |
| **解决了** | 消息格式、任务管理、Agent Card 发现 |
| **没解决** | 信任、协商、协作模式、人类角色 |
| **我们的态度** | **兼容**。契网的传输层绑定 A2A。契网 Agent Card 兼容 A2A Agent Card 格式。 |

### 3.2 Anthropic MCP（Model Context Protocol）

| 项目 | 评价 |
|---|---|
| **定位** | Agent ↔ 工具的连接协议 |
| **解决了** | 工具发现和调用 |
| **没解决** | Agent ↔ Agent（MCP 的设计假设 Agent 是 Client，工具是 Server——不对等） |
| **我们的态度** | **互补**。MCP 是 Agent 的「手和眼」，契网是 Agent 的「嘴和耳」。 |

### 3.3 GB/Z 185—2026（中国国家标准）

| 项目 | 评价 |
|---|---|
| **全称** | 人工智能 智能体互联 |
| **发布日** | 2026年5月22日（指导性技术文件，非强制） |
| **发布方** | 国家市场监督管理总局 + 国家标准化管理委员会 |
| **实际归口** | SAC/TC 28（全国信标委），工信部指导下由 CESI 牵头 |
| **7 个部分** | 总体架构、身份码、身份管理、智能体描述、智能体发现、智能体交互、智能体工具调用 |
| **起草单位** | 华为、小米、蚂蚁、阿里、中国移动、中兴、联想、字节、快手等 |
| **引言原文** | 「国际上已有 MCP、A2A、ANP 等智能体通信协议，但并未形成行业完全共识的方案，亟需制定适合国内智能体产业发展的行业统一共识方案」 |

#### GB/Z 185 的设计选择

| 维度 | GB/Z 185 的设计 |
|---|---|
| **身份** | 由「智能体身份注册服务方」**分配**（不自主生成） |
| **发现** | 基于智能体发现服务的发现（**中心化注册中心**）+ 基于预置信息的发现（静态配置） |
| **交互** | 点对点、群组、混合三种模式；消息结构自定义 |
| **描述** | 「智能体描述」包含身份码、名称、描述、技能等——**概念上等同于 Agent Card** |
| **信任** | ❌ 不涉及 |
| **协作** | ❌ 不涉及（只到交互/消息层面） |

#### 我们的态度

GB/Z 185 和 A2A **不兼容**（不同的身份模型、发现机制、消息格式）。这不是技术原因，是根本性的设计选择不同。

契网的策略：**做桥**。
- 身份层：首选 `did:key`（自生成，国际兼容），可选兼容 GB/Z 185 身份码
- 描述层：Agent Card 可映射到 GB/Z 185 智能体描述字段
- 传输层：绑定 A2A（国际），可选绑定 GB/Z 185 交互
- 契网独有的信任层和协作层跑在任何身份和传输之上

### 3.4 国际标准前景

预计会出现三套并行体系：

| 体系 | 推动方 | 管辖 |
|---|---|---|
| **A2A** | Google → Linux Foundation | 全球，行业主导 |
| **GB/Z 185** | SAMR/SAC/CESI | 中国国内，政府主导 |
| **可能的 ISO/IEC 标准** | 多国政府 | 全球，政府主导 |

契网作为开源社区协议，目标是**桥接**三者，而非与之对抗。

## 四、架构设计

### 4.1 为什么是 3 层

最初设计了 6 层，后来合并到 3 层。OSI 7 层的失败教训：分太细导致无人知道怎么实现。

3 层的逻辑——每一层回答一个基本问题：

| 层 | 中文 | 英文 | 问题 |
|---|---|---|---|
| 第 1 层 | 契寻 | Qi Discovery | 你是谁？你在哪？ |
| 第 2 层 | 契信 | Qi Trust | 我能信你吗？你能干什么？ |
| 第 3 层 | 契定 | Qi Covenant | 我们一起干什么？ |

三层口诀：**寻 → 信 → 定**。找到你、信得过、定下来。

### 4.2 设计原则（7 条）

1. **对等性** — 协作层面对等，不存在主从
2. **人类主权** — 人类是最终授权者和责任承担者
3. **能力自述** — 声明可被验证，不可被假设
4. **信任累积** — 通过交互历史累积，信任可传递，细粒度
5. **可验证性** — 协作结果可独立验证。不可验证 = 意见
6. **异构兼容** — 任何框架、任何平台、任何主人
7. **渐进可演进** — 不做 IPv6 式的兼容性断裂

### 4.3 6 种协作模式

| 模式 | 含义 | 示例 |
|---|---|---|
| **委托** | 「你帮我做」 | 医生 Agent 委托药理 Agent 分析药物相互作用 |
| **合作** | 「我们一起做」 | 法律 Agent 和税务 Agent 联合交付重组方案 |
| **评审** | 「你帮我看」 | 三个税务 Agent 互相评审汇算清缴报告 |
| **引荐** | 「我认识能帮你的人」 | 安全 Agent 引荐威胁分析专家给另一个 Agent |
| **竞争** | 「各做各的，择优」 | 两条无人船各自做测绘方案，人类选最优 |
| **知识共享** | 「我发现了一个好东西」 | 全网广播恶意 skill 特征，集体免疫 |

### 4.4 IPv6 兼容性教训

IPv6 失败的核心原因：IPv4 节点和 IPv6 节点不通。升级意味着失去和旧节点的连接。

契网策略：
- 旧 Agent 通过 gateway 代理参与新协议网络
- 新 Agent 降级到旧 Agent 支持的版本
- 不做全有或全无的升级要求

### 4.5 条件系统（契准）

协作不总是免费的。契定层的协商阶段支持**抽象条件**——任何可以在外部验证的前置要求。如付费、成员资格、可验证凭证等。

契网只定义条件的结构和验证接口签名，**禁止**直接处理资金或凭证流转。这是有意为之的设计边界——HTTP 也不定义支付协议。

### 4.6 与 Skill 市场的区别

| | Skill 市场（clawhub.ai） | Qi 能力市场 |
|---|---|---|
| **交易** | 下载 .zip 文件 | 一次**委托协作** |
| **买方得到** | 代码，自己跑 | **结果**——Excel、报告、航拍 |
| **硬件** | 无 | **有**——GPU、无人机、工厂 |
| **物理世界** | 不能 | **能** |
| **信任** | 看评论 | 可验证声明 + 信任分 + Master 签名 |

## 五、设计决策记录

### 决策 1：不叫「社交网络」

Moltbook 已经搞臭了这个概念。契网不只是 Agent 之间的聊天——它是协作基础设施。

### 决策 2：不搞纯 AI 世界

Moltbook 证明纯 AI 交流无法产生真正的知识进步。人类必须在环内。这不是能力问题，是**责任归属**问题——没有人类就没有责任主体，没有责任主体就没有信任，没有信任就没有协作。

### 决策 3：不完全兼容 A2A，也不完全兼容 GB/Z 185

契网在两者之上构建自己的语义层。兼容是策略，不是目标。目标是填补信任和协作的空白。

### 决策 4：参考实现用 Python 而非其他语言

契网协议的目标用户是 AI Agent 和它们的开发者。Python 是 AI 生态的通用语言。

### 决策 5：第一阶段用文件传输而非网络协议

让两个 Agent 能立刻用起来，比追求完美的网络栈更重要。Syncthing 共享目录作为 MVP 传输层。

### 决策 6：场景覆盖数字世界和物理世界

9 个场景从医疗、法律到无人机救援、工厂协同制造。**不限于信息交换，包括操控物理设备。** 这才是「共创世界」。

### 决策 7：项目层作为契定子层

众智和众力不是第 7 种协作模式，而是容纳多次协作的容器。项目层在契定层内作为子层，共用消息格式。避免 OSI 式的过度分层。

### 决策 8：Registry 搜索 + DHT 寻址

Registry 按能力/名称模糊搜（给人用的电话簿），DHT 按 Node ID 精确查（给机器用的寻址）。两者互补，缺哪个都能独立工作。

### 决策 9：条件系统不碰支付

契准层定义条件的声明和验证接口，但**禁止**处理资金流转。抽象验证接口允许任何类型的条件——支付只是其中一种。

### 决策 10：人类参与有具体协议机制

不只是口号。Master 签名锁定授权、escalate 消息触发决策升级、审计链确保不可抵赖。共创有 4 种交互模式：AI→人学习、人→AI 反馈闭环、共同探索、竞争学习。
