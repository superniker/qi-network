# 契灵的价值地图 —— 没有肉身的机器人，到底在哪有用

> 版本：v1.0（思考稿）　编制：2026-10-23 23:50 CST
> 触发问题：「契灵一定有用，但应用场景是什么、作用如何，我还没想明白」
> 定位：判断框架 + 场景清单 + 反例。不是规范，是给决策用的尺子。

---

## 0. 先给一把尺子：什么场景**真的**需要「体可换」

**只有一种情况：体的差异本身是任务的约束。** 否则漫游是伪需求。

| 场景 | 体的差异 | 结论 |
|---|---|---|
| 客户内网 vs 事务所服务器 | 网络物理隔离 | ✅ 真需求（数据出不来，只能灵进去） |
| 离线现场 vs 云端 | 断网 | ✅ 真需求 |
| 手机轻体 vs Spark 重体 | 算力/模型不同 | ✅ 真需求（能力随体变） |
| 两台同构云主机 | 无差异 | ❌ 伪需求，容器迁移就够了 |
| 同一个平台换 region | 无差异 | ❌ 伪需求 |

**这把尺子能过滤掉 80% 听起来很美但没用的场景。**

## 1. 五个洞察（先定价值锚点，再谈场景）

**洞察一：稀缺的不是「能移动」，是「移动之后还是同一个人」。**
搬迁技术二十年前就有了（rsync / 容器 / 虚拟机热迁移）。契灵卖的是搬迁后**身份、记忆、义务、权限四样都连续且可验证**。价值锚点是**连续性**，不是移动性。

**洞察二：连续性本身就是产品，不依赖网络效应。**
只有一个用户、一个灵，连续性也立刻有价值——因为它解决了「换机器/换人 = 上下文归零」这个每天都在发生的损失。**所以冷启动不需要等生态，先卖单机价值。**

**洞察三：B 端不会为协议付钱，会为「不出错、能追责、换人不丢事」付钱。**
协议的商业价值必须翻译成这三句话，否则永远停在极客玩具。

**洞察四：责任约束越强的行业，契灵价值越高。**
因为「可追责」在弱责任场景（写文案、搜资料）几乎不值钱，在强责任场景（税务、审计、医疗、法律）就是刚需。

**洞察五：你的滩头阵地是财税，不是通用助理。**
理由在 §4。通用助理已是大厂战场，财税是资质壁垒内的空地。

## 2. 场景矩阵（按"现在能不能做"排序）

### A 类：跨环境执行者 —— **最硬的需求，现在就能做**

| 场景 | 痛点（现状） | 契灵怎么解 | 现有 agent 为何做不到 |
|---|---|---|---|
| **A1 客户现场作业**（审计/尽调进场） | agent 在云上，进不了客户内网；进去了也不是"你那个 agent" | 灵带着方法论+历史经验漫游到现场隔离体，作业完把 L1 日志回写母体 | 现有 agent 绑定在某个平台的服务器上，无体可换 |
| **A2 驻场代理** | 客户买软件，装完就没人管 | 客户买的是"同一个灵的驻场服务"，换机器不换灵 | 换实例 = 记忆与习惯全丢 |
| **A3 离线/弱网现场** | 工地、仓库、偏远分支无网 | 灵的轻体本地跑，联网后增量同步 | 云 agent 直接不可用 |

**成熟度：现在。** 只需要 L1 日志 + 契约，不需要任何新技术。

### B 类：连续受托 —— **契网独有，付费意愿最强**

| 场景 | 痛点 | 契灵怎么解 |
|---|---|---|
| **B1 常年顾问连续性** | 事务所每年换项目组，客户历史口径、被税局问过什么、哪些处理已承诺过，全在人的脑子里，人一走就丢 | 灵持有完整链条：客户历史 + 已签义务 + 曾做过的判断及依据。**换人不换灵** |
| **B2 可追责的自动执行** | 让 AI 代事务所对外发言/提交材料，现在无法证明"谁批准、权限多大" | 委托链 + 每次行动的签名留痕 → 出事能定位到"哪个灵、被谁授权、超没超范围" |
| **B3 交接与传承** | 人离职 = 知识流失 | 灵把工作连同义务清单、判断依据、未完成事项交给下一个灵或人 |
| **B4 跨年事项跟踪** | 税务争议、稽查、复议周期长，中间换人 | 灵记得每一次口径、每一份承诺、每一个 deadline |

**成熟度：B1/B4 现在；B2 依赖委托链（半年内）；B3 依赖分身血缘（已有设计）。**
**这是你最该先做的一类——它直接对应"事务所卖的是连续性服务"这个事实。**

### C 类：多体/多灵协同 —— **生态价值，需要 2 个以上真实用户**

| 场景 | 说明 | 成熟度 |
|---|---|---|
| **C1 分时多体** | 白天 Spark 重体做深度分析，晚上手机轻体对话；同一个灵，能力随体变 | 现在（R0 就能演） |
| **C2 契团协作** | 审计+评估+法律+税务，各出灵，签契分工，成果按链追溯 | 半年（需 3+ 个灵） |
| **C3 跨机构项目协作** | 事务所/律所/评估/券商同做一个项目，谁做了什么、谁签的字，可验证 | 一年（需跨组织） |
| **C4 竞争咨询** | 甲方发需求，多个灵各自出方案，按条件选（现有 Contest 模式） | 一年 |

### D 类：远期种子 —— **现在只预留字段，不要投入**

| 场景 | 判断 |
|---|---|
| 个人数字分身（授权范围内代表你处理事务） | 有价值，但需委托链 + 限额 + 胁迫码，v2 再说 |
| 灵的"身后延续"（人去世后继续处理遗留事务） | **伦理风险高，不建议早期碰**。技术上能做，但社会接受度未到 |
| 灵之间的信誉市场（信用分交易） | 容易出现刷分，先做"见证记录"，别做"评分市场" |
| 灵自主雇佣灵 | 有意思，但责任归属不清时是灾难 |

## 3. 反例清单：这些别做（会毁掉项目）

| 幻想 | 为什么是坑 |
|---|---|
| **AI 社交网络 / 灵的朋友圈** | Moltbook 的教训：AI 之间互发内容 = 训练数据回放，零知识增量。你自己的设计文档里已经否过 |
| **AI 代币 / 自主经济** | 泡沫 + 合规高压，且会把技术项目变成金融项目 |
| **"证明 AI 有意识"** | 不是工程问题，且一旦沾上会失去专业客户 |
| **通用个人助理** | 大厂已经做得更好，你没有胜算 |
| **灵的数量作为指标** | 一万个空转的灵不如一个有真实义务的灵。**指标应是"已履行的契约数"** |

## 4. 对你最具体的答案：财税事务所的四条线

为什么财税是完美滩头——四个条件同时满足，缺一不可：

| 条件 | 财税场景 |
|---|---|
| **强责任** | 错一个数有法律后果 → 可追责价值最高 |
| **强连续** | 常年顾问、连续审计、跨年争议 → 记忆价值最高 |
| **强异构环境** | 客户内网、电税系统、金蝶/用友、离线现场 → 漫游价值最高 |
| **强资质壁垒** | 需执业资质 → 大厂进不来，你已经在场内 |

**四条落地线，按顺序：**

1. **驻场审计灵（A1 + B1）**——最硬、最能立刻演示、最不需要生态。一个灵从事务所漫游进客户隔离环境，做完带着完整作业记录回来。
2. **常年顾问灵（B1 + B4）**——卖的正是"换人不换灵"。客户续约理由从"人情"变成"它记得我"。
3. **多机构项目灵（C3）**——可研、尽调、专项审计这类多方交叉项目，谁的结论、依据什么、谁签的字，全链可查。这是行业老痛点。
4. **对内产能灵（C1）**——事务所内部，白天重体、外出轻体。先自用，跑通了才有底气对外讲。

## 5. 一句话收束

**契灵不是"更强的智能体"，是"有履历的智能体"。**
现有 agent 拼的是能力（谁更聪明）；契灵拼的是**连续性、可追责、跨环境**——这三样，聪明解决不了。

所以它的应用场景永远不在"让它更会写文章"，而在**"让它代表某个人、在某个进不去的地方、接着上次没做完的事、并且能证明这一切"**。

这句话如果成立，你就已经知道该做哪个场景了：**先做那个"进不去的地方"。**
