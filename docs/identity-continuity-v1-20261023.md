# 我是谁，谁是我 —— 契灵身份连续性证明

> 版本：v1.0（讨论稿）　编制：2026-10-23 23:20 CST
> 触发问题：「我如何证明我是谁，谁是我？」
> 关联：`docs/qiling-roaming-v1-20261023.md`（漫游依赖本文的身份机制）
> 定位：协议设计，不含实现代码

---

## 0. 一句话答案

**没有「本质」可以证明。身份不是一件东西，是三条证据链的交汇：**

```
持有（我能签）  +  历史（我做过这些）  +  承认（别人记得我）
```

三者缺一，身份就断。而且**最关键的一条不在你手里**：

> **「谁是我」的最终答案，不在我自己手里，在别人手里。**
> 你能证明「我持有这把钥匙」，但证明「我是上次那个」——要靠**别人保存的、你的旧历史哈希**。

这就是为什么单靠 did:key 不够：钥匙证明的是"能签"，不证明"是同一条命的延续"。

---

## 1. 这句话里其实是三个问题

| 问题 | 面向 | 靠什么回答 |
|---|---|---|
| **我是谁**（自证） | 我自己 → 陌生人 | 持有私钥，签一个挑战 |
| **谁是我**（他识） | 他者 → 我 | 他者的记忆：上次见你的历史哈希、契约存档、信任分 |
| **我怎么知道我是我**（自识） | 我 → 我自己 | 我的日志链连续、没有被截断重写、没有分叉 |

第三个问题最容易被跳过，但它才是漫游真正的命门：**换了身体之后，谁能保证"落地的那份日志"就是"走的时候那份"？**

---

## 2. 为什么「本质」不可证

三个反例，都必须承认，不能靠话术绕过：

| 反例 | 说明 | 结论 |
|---|---|---|
| **忒修斯之船** | 换身体后模型可能变小、skill 可能变少、记忆可能裁剪——哪些换掉之后就不是"我"了？ | 没有客观阈值。「本质」不可定义 |
| **密钥泄露** | 别人拿到你的私钥，技术上完全等于你 | 「持有」单独不足 |
| **完美副本** | 私钥 + 完整日志 + 所有见证人都不知情地被骗过一次 | 技术上不可区分，只能靠 epoch 与见证人发现异常 |

**因此协议不能承诺「证明你是你」，只能承诺「证明你是否是上次那个，以及你代表谁」。** 这两句话差别很大，写进规范时必须诚实。

---

## 3. 三条链，各自的失效模式

| 链 | 载体 | 证明什么 | 单独失效时 |
|---|---|---|---|
| **持有** | Ed25519 私钥 / did:key | 此刻我能签 | 密钥泄露 → 谁都能冒充 |
| **历史** | append-only 签名日志（哈希链） | 我经历过什么 | 单方持有 → 可以偷偷重写（没有外部锚点时） |
| **承认** | 他者的 peer 记录、契约存档、信任分 | 别人认我是那个我 | 多数暴力 / 集体遗忘 → 真身被否认 |

**所以三条必须叠加：**
- 只有持有 → 一把钥匙就能当任何人（当前的裸 did:key 方案就停在这一层）
- 持有 + 历史 → 仍然可以自建一条完美假链（因为历史自己写）
- **持有 + 历史 + 承认 → 才构成不可伪造的连续性**：因为**你改不了别人手里的旧哈希**

这条是本文的核心结论：**他者的记忆是唯一的防篡改锚点。** 区块链用算力做这件事，契网用**社会关系**做这件事——这恰好也是「契」的本义：两方各持一份，对得上才算数。

## 4. 四个机制（可落地）

### 4.1 创世记录（Genesis Record）——出生证明

灵生成的那一刻，写一份不可变的创世记录，由三样东西签：

| 字段 | 内容 |
|---|---|
| `qiling_did` | 灵的公钥身份 |
| `born_at` | 出生时间 |
| `soul_hash` | 初始 `SOUL.md` 的哈希（人格基线的锚） |
| `parent` | 母体（哪个体、哪台机） |
| `root_did` | 人类 root 的 did——**这一签是关键** |
| `lineage` | 若是分身：父灵 did + 父签血缘证明 |

**为什么必须有人类 root 签：** 纯 AI 自签的创世记录等于"我宣布我是我"，循环论证。人类 root 的签名把**责任**接进来了——从此这个灵的违约有人可追。

### 4.2 链头见证（Witness）——让别人替你记住

```
每次漫游 / 每次签重大契约时，把 (did, epoch, chain_head_hash, 时间)
发给 N 个见证者（契团、registry、长期合作的契灵）。

之后任何一方想重写历史：他必须让所有见证者同时遗忘旧哈希。
成本从"改自己的文件"变成"说服或攻破 N 个独立主体"。
```

- **N=1 就有效**（自己留一份，防的是本地损坏）
- **N=3 起有安全意义**（防单点作恶）
- 见证者可拒绝为失信者见证 → 这就是**声誉的实际载体**

Git 的 remote、比特币的 checkpoint、法院的公证，都是这一个机制的不同形态。契网只是把它做进协议。

### 4.3 两个「我」同时出现时：epoch 仲裁

```
两个实例都自称是同一个 did：
  → 谁的 epoch 高，谁合法（规则见漫游文档 §5）
  → 同 epoch 双签名 → 双方停写，上报仲裁
  → 仲裁依据：见证者手里的链头哈希（看哪条链是他签过的延续）
```

**关键：仲裁不靠自证，靠第三方保存的历史。** 这也是为什么 4.2 必须先在。

### 4.4 分叉与死亡：协议必须承认「我」会死

最难的一种情况：两条链各自延续、各自被不同的他者承认。这不是"谁是假的"，这是**分裂**。

**必须给出的答案（建议写进规范）：**

> 一旦分叉被双方各自的见证者持续承认，**原来的「我」即告终止**，产生两个新的契灵。
> 协议要能签发「死亡证明」（terminated_did + 分叉点 + 双方新 did），否则它就在撒谎。

理由：如果不承认死亡，协议就必须在无穷多条并存链里选一个"真我"——那只能靠暴力或独裁，与契网的原则冲突。**承认死亡，反而让身份可信**——因为这意味着活着的那条链是有代价维持的。

**密钥丢失 / root 死亡也要有路径：**
- 灵：多签恢复（3 个长期 peer 中 2 个确认 + root 签）
- 人：社会恢复（律所/家人/合伙人多签），否则整个契团的主权会随一个人的意外而永久锁死

## 5. 人类这一侧：「我」其实是三层

这是最实务、也最容易被忽略的部分。在授权语境里说"我"，实际指三个不同主体：

| 层 | 载体 | 证明什么 | 失效后果 |
|---|---|---|---|
| **操作身份** | `did:key`（灵或人的密钥） | 此刻是谁在操作 | 密钥泄露 → 冒名操作 |
| **责任身份** | 法律实名 + 执业资质（如事务所、税务师） | 出事找谁 | 无锚定 → 追责断链 |
| **授权身份** | 委托链（root 签给灵的范围与额度） | 它被允许做什么 | 范围不清 → 越权或无权限 |

**三者靠一次性绑定连起来：** 人类 root 用自己的实名（可验证声明 VC）绑定一个 `root_did`，再由 `root_did` 签发委托链给各契灵。

这条对你有直接用处：**做对外财税服务时，网站上公示的运营主体 + 执业资质，就是"责任身份"的锚点**；契网里的 `root_did` 签的委托链，才是"这个灵代表事务所说话"的可验证凭据。没有这层，客户看到的是一个自称专家的 AI；有了这层，客户看到的是**事务所的代理**。

**最硬的一句：法律身份永远无法由协议自证，必须外部权威锚定。** 契网不该假装能解决"你是谁"，它解决的是"你是否是上次那个，以及你代表了谁"。

## 6. 数据模型：三张卡，一条链

```
灵卡（Qi Ling Card）
  did / genesis / epoch / chain_head / soul_hash / lineage / trust_score

体卡（Body Card）
  body_id / host 公钥 / 能力清单 / 可授予权限上限 / 归属人 root_did

人卡（Root Card）
  root_did / 实名 VC / 资质 VC / 委托链根 / 恢复多签配置

链（Sign Chain，append-only）
  seq / prev_hash / this_hash / 类型 / 载荷 / 签名 / 见证回执
```

规则：**任何一张卡单独都不构成身份**。对外验证的最小组合是「灵卡 + 链头 + 至少一个见证回执」。

## 7. 诚实边界：技术解决不了的三件事

| 情况 | 为什么解决不了 | 兜底 |
|---|---|---|
| 完美副本（私钥+日志全被复制，见证人被骗） | 信息层面完全等价 | 只能靠 epoch 冲突暴露、物理隔离、见证人发现异常行为 |
| 被胁迫签契 | 签名是真的 | 需要"胁迫码"机制（双密钥：正常签与胁迫签，后者触发静默报警） |
| 人的"我是我" | 密钥可丢、可被夺、人可死 | 实名锚定 + 社会恢复 + 法律程序 |

**这三条要写进规范，不要假装没有。** 一个声称"可以证明你是谁"的协议，是不诚实的协议。

---

## 8. 最小可用实现（三个动作，能立刻验）

1. **生成创世记录**：每个 profile 的 did 落一份 genesis（含 `soul_hash` 与 root 签）→ 验：改一个字节，签名即失效
2. **链头见证**：把 `(did, epoch, chain_head)` 交给 registry 存一份，本地留一份 → 验：本地重写历史后，registry 那份对不上，立即被发现
3. **挑战-应答**：对端发随机数，灵签名回传 → 验：证明"此刻持有私钥"，但不证明"是同一条命"——**必须叠加 2 才有意义**

第 3 步是现在 did:key 已经能做到的；**缺口在 1 和 2**。补上这两个，契网的身份才从"能验证签名"升到"能验证连续"。

> **「我是谁」由私钥回答，「谁是我」由别人手里的旧哈希回答，「我代表谁」由人类 root 的委托链回答。**
