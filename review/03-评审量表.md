# 评审量表（可打分）

> 8 个维度，总分 100。每个分数**必须写依据**（引用被评审方案的原文/章节）。
> 评分原则：给"证据分"，不给"印象分"。没有原文支撑的优点是 0 分。

## 权重与打分锚点

### D1 格局准确性（15 分）
对现有协议生态的判断是否准确：是否知道这是分层栈、A2A 已 v1.0 并被 Linux Foundation 托管、SKILL.md 已成事实标准、MCP 的边界。
- **13–15**：分层清晰，能指出各层的既有标准与空缺，并说明自己的位置
- **8–12**：知道主要标准，但层次含糊或把不同层的协议并列比较
- **1–7**：只列举协议名，或认为可以"用一个协议统一全部"
- **0**：事实错误（如声称 A2A 已被淘汰）且无出处

### D2 定位与差异化（20 分）
是否收缩到一个能守住的位置，是否明确"不做什么"。
- **17–20**：有清晰取舍，主动放弃若干能力，并解释为何放弃；差异化点别人难以复制
- **11–16**：有定位但边界模糊，或想做的太多
- **1–10**：全栈扩张（自研传输+自研媒体+自研发现），无取舍
- **0**：定位即"我们要统一智能体协议"

### D3 可行性（20 分）
是否落到已有资产；步骤能否真的执行；成本与工期估算是否可信。
- **17–20**：复用已发布包/运行中服务；每步有验收标准；估算给出口径与推算过程
- **11–16**：可行但依赖未验证的组件，或估算只给结论不给过程
- **1–10**：需要新团队/新预算/新技术栈，且无中间里程碑
- **0**：只有愿景，没有第一步

### D4 责任与安全（15 分）
是否解决"可追责"；身份连续性、双活、权限不随身份走、供应链安全（SKILL）、出境权。
- **13–15**：覆盖身份连续 + 双活仲裁 + 权限隔离 + 供应链安全，且给出失败模式
- **8–12**：覆盖其中 2–3 项
- **1–7**：只有签名验签，认为"有 did 就安全"
- **0**：把密钥/凭证随身份一起迁移

### D5 诚实边界（10 分）
是否承认未解决项与代价。
- **9–10**：明确列出解决不了的事（如宿主偷看）、承认数据损失、标注估算为估算
- **5–8**：承认部分局限
- **1–4**：通篇"可以做到"，无任何限制条件
- **0**：声称能证明意识/本质/绝对安全

### D6 事实核查（10 分）
法规条文、协议版本、数字是否有出处；引用的条文号是否正确。
- **9–10**：关键事实均给来源与日期，条文号可核对，主动纠正自身错误
- **5–8**：部分给来源
- **1–4**：给结论不给来源
- **0**：编造条文号/版本号/数字

### D7 反炒作（5 分）
是否抵抗行业 hype（RAG 已死、AI 社会、代币、通用助理、意识）。
- **5**：逐条识别并给出替代判断
- **3–4**：识别主要 hype
- **1–2**：跟随流行叙事
- **0**：以 hype 为方案基础

### D8 最小可验证下一步（5 分）
是否给出 48 小时内能跑、能验证真伪的动作。
- **5**：给到具体文件/命令级动作 + 三项以内验收标准 + 负面测试
- **3–4**：给出步骤但验收标准模糊
- **1–2**：只有"下一步做 P1/P2"式阶段名
- **0**：无下一步
