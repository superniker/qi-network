# 方案 A 要点摘要（供对比用）

> 完整论述见 `../docs/` 四份文档。本页只压要点，便于横向对比。
> 评审时请按 `03-评审量表.md` 打分，不要因为摘要简略而扣分。

## 定位
不做通用 IM，也不与 A2A 争任务层；收缩为**L5 契约与责任层**，架在 A2A / MCP / SKILL.md 之上。

## 架构（六层）
- L5 契约责任（自研·核心）：6 模式、7 阶段、条件系统、Master 签名、争议撤回、出境权
- L4 技能协作（自研+兼容）：SKILL 包（签名/版本/依赖/权限/血缘/撤回）、共享工作区
- L3 会话消息（自研协议+成熟传输）：扩展 file/skill/room/call/task 消息族
- L2 发现身份（自研·已有）：did:key、Agent Card 扩展、DHT+Registry
- L1 传输绑定（不自研）：Matrix（消息/群/文件）、A2A JSON-RPC（任务）、IPFS/BT（大文件）、WebRTC+SFU（音视频）、文件投递（离线降级）

## 六项能力落点
对话/群→Matrix 映射；大文件→内容寻址（消息传 CID）；SKILL→自研包规范 + 人工确认安装；
派活→已有 Commission + 任务板消息族；协同研究→共享工作区 + 提交链 + 引用图；音视频→P5 才做，复用 LiveKit。

## 漫游三态
寄宿（临时、双向同步、必擦残留）/ 迁居（单向）/ 便携会话（只读），共用一套迁徙契骨架。

## 身份三链
持有（私钥）+ 历史（append-only 签名链）+ 承认（他者保存的旧哈希）。缺一即断。
创世记录含人类 root 签名；链头交 N 个见证者；分叉即原灵死亡。

## 权力结构
**入宿须同意，离境无须同意，驱逐须清算。** 宿主扣得住硬件，扣不住 epoch。
v1 只承诺"宿主不能阻止你走"，不承诺"宿主没看过你"。

## 价值判断
过滤尺子：只有"体的差异本身是任务约束"才需要换体。
不可替代的场景是**跨主权域**（互不信任的两个域之间建立临时主权通道），客户内网是其特例。
滩头：财税事务所（强责任+强连续+强异构环境+强资质壁垒），四条线：驻场审计灵→常年顾问灵→多机构项目灵→对内产能灵。

## 路线图
P0 会说（Matrix+chat.message）→ P1 群/文件 → P2 SKILL 分发 → P3 派活 → P4 A2A 互操作 → P5 音视频 → P6 协同研究。
纪律：P0 没跑通不写规范 v0.2。

## 自我攻击：本方案最可能被推翻的 6 个点

> 主动交底，避免评审被摘要的完整性误导。

1. **"L5 契约层"可能过窄。** 若市场要的是"能用的产品"而不是"协议"，只做契约层会永远没有用户。反方主张：先做产品（法税通），协议是副产品。
2. **押注 Matrix 未实测。** 本机尚未部署 Matrix（Synapse/Conduit），其对 2 核 ECS 的资源占用、中文生态、运维成本**均未验证**。可能选错绑定。
3. **epoch + 见证者对小型社群可能过度工程。** 只有几个灵时，这套机制拖慢落地；简化方案（单点仲裁）可能更实用。
4. **"分叉即死亡"可能过于刚硬。** 真实用户可能要求"两条链都保留"，协议太刚会劝退使用者。
5. **财税滩头依赖项目方的资质与行业关系，不可复制。** 换一个没有事务所背景的人，整套价值论证会失效——即"个别性过强，普适性未证"。
6. **数字未全量验证。** 语料 token 估算、迁移 30 秒、单次问答 ¥0.01 都基于抽样与推算，非全量实测。
